# Eyas

Eyas is a real-time, piloted rotorcraft flight dynamics model: a C++20 static
library that a host simulator links and calls once per frame. Its reference
aircraft is the UH-60A Black Hawk, built from public data (NASA's GenHel
report, CR-166309, and the flight-test and simulation reports listed in
[CLAUDE.md](CLAUDE.md)).

- **Physics:** a 6-degree-of-freedom rigid body with a blade-element main rotor
  (rigid flapping blades on an offset hinge, Pitt–Peters dynamic inflow with
  tip loss and wake curvature, the vortex-ring state, ground effect), GenHel's
  tail rotor, fuselage, empennage and landing gear, and its flight control
  system (SAS, pitch bias actuator, flight path stabilization). The rotor
  speed is a degree of freedom, driven by T700 engines with their fuel
  controls, clutches and governors, so autorotation and engine failures fly.
- **Real time:** `advance()` allocates nothing, throws nothing, does no I/O and
  is bit-for-bit deterministic. A 60 Hz frame costs 0.3–0.75 ms on average on
  a desktop, at worst about 1.4 ms (`eyas_bench`; docs/INTEGRATION.md §6).
- **Data-driven:** aircraft are YAML files with CSV tables, loaded at start-up.
  Every value cites its source, and a value without one is tagged
  `!placeholder` and listed at load.
- **Validated:** against flight test and published simulation results
  (trims, step responses, frequency responses, engines). The results,
  including the open gaps, are in [docs/VALIDATION.md](docs/VALIDATION.md).

## Status

Milestones M0–M8d and M9's ground effect, rotor speed and engines, and wake
curvature are done. Next in M9: blade lag, Peters–He inflow, dynamic stall and
turbulence (issue #43). M8e (timing on the target hardware, the host adapter,
the piloted evaluation) waits for the host system. The roadmap is in the
GitHub issues, by milestone.

## Quick start

Linux with GCC 11 or newer (or Clang) and CMake 3.24 or newer. The library's
dependencies (Eigen, yaml-cpp, GoogleTest) are fetched at configure time. The
pilot station's window needs GLFW 3.3 and OpenGL from the system (e.g.
`libglfw3-dev`); without them it is built headless only (`--headless`, with
FlightGear or a script).

```bash
cmake --preset release
cmake --build --preset release
ctest --preset release                     # the whole suite (several minutes)

# Fly a doublet from a 60 kt trim and write the state history:
./build/release/examples/eyas_drive --config data/uh60a/uh60a.yaml \
    --controls examples/drive/doublet_10s.csv --trim-speed 60 --afcs sas,pba,fps \
    --out doublet.csv

# Fly it yourself (mouse, gamepad, joystick, or FlightGear's view and sticks):
./build/release/examples/eyas_pilot_station --config data/uh60a/uh60a.yaml \
    --input mouse --start hover
```

The other presets are `debug`, `relwithdebinfo`, `asan` and `asan-fast`.
[examples/README.md](examples/README.md) describes the driver, the reference
adapter and the pilot station (with FlightGear and a HOTAS).

## Using Eyas in a host

```cpp
#include "eyas/model.hpp"

eyas::GeodeticOrigin origin{0.6566, -2.1359, 4.0};  // [rad, rad, m MSL]: the host's airfield
eyas::Model model = eyas::Model::from_file("data/uh60a/uh60a.yaml", origin);
eyas::TrimCondition c;
c.airspeed = 30.0;                        // [m/s] true airspeed
c.afcs = {true, true, true, true};        // SAS (both channels), pitch bias, FPS
const eyas::TrimResult trim = model.trim(c);   // init-time; check trim.converged

eyas::Controls controls = trim.controls;  // the host's cockpit controls, each frame
eyas::Environment env;                    // the trim's air: ISA, no wind
for (;;) {                                // once per host frame
    model.advance(controls, env, 16'666'667);  // [ns]
    const eyas::AircraftState& s = model.outputs();
    draw(s.latitude, s.longitude, s.altitude, s.q_nb);  // the host's own
}
```

[docs/INTEGRATION.md](docs/INTEGRATION.md) is the host integration guide:
building and linking, the lifecycle, units and sign conventions, the
real-time contract, every input and output, status flags and the known
limits.

## Aircraft

| Config | Engines |
|---|---|
| `data/uh60a/uh60a.yaml` | GenHel's T700 model: governed rotor speed with the engine-speed trim, no power levers or fuel shutoffs |
| `data/uh60a/engine_ballin/uh60a.yaml` | Ballin's component-level T700s (NASA TM-100991), one per engine: power levers, fuel shutoffs, failures and relights |

Both carry the whole flight control system. The configs are generated by
`tools/build_uh60a_config.py`; edit the generator, not the YAML. The other
YAMLs under `data/uh60a/` are the validation variants (each report's weight,
CG and atmosphere).

| Path | Contents |
|---|---|
| `include/eyas/` | The public API: `Model`, `AircraftState`, the value types, `InitError` |
| `src/` | The library: `core/` (rigid body, integrator, component interfaces), `rotor/`, `airframe/`, `engine/`, `control/` (flight control system), `env/` (atmosphere, air data, geodesy), `analysis/` (trim, linearization), `sim/` (executive, `Model`, config readers), `util/` |

| `tests/` | Unit tests, exact-equation references, validation generators |

| `docs/` | The design spec, decisions, data gaps, validation, integration guide |

## Conventions

SI units throughout the API, radians for angles, integer nanoseconds for frame
time. Frames follow Padfield: NED inertial (`_n`), body forward-right-down at
the CG (`_b`). Pedal is + right, cyclic + right and + forward, collective 0 to
1 up. [docs/INTEGRATION.md](docs/INTEGRATION.md) has the full table.
